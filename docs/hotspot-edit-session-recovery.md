# スポット添付時の編集トークン失効からの復旧

2026-09-11のテストGAS `/dev` の実行ログで、07:25:51の `getAudioVendorBundle` と07:26:15の `saveHotspot` が、いずれも `assertEditToken_` のキャッシュ検証で拒否されていた。音声の選択後と写真の保存時に同じ問題が発生する。従来の画面では認証エラーが一般的な読み込み・通信エラーになり、再試行しても失効したトークンを送信していた。

スポットの新規保存・更新と音声エディターの読み込みは、認証拒否の場合だけ元の編集URLを再認証する。`refreshEditToken` は `doGet` と同じ有効キーの判定と6時間の有効期限を使う。既存のキー移行条件・キー変更時の失効・公開画面の編集拒否は維持する。

クライアントは [google.script.url.getLocation](https://developers.google.com/apps-script/guides/html/reference/url) で現在の編集URLのパラメータを取得する。共有キーをローカルストレージやログへ保存せず、更新した一時トークンのみをメモリに保持する。[CacheService](https://developers.google.com/apps-script/reference/cache/cache) の有効期限は保証ではなく、早期退避にも同じ復旧処理で対応する。

再送は一度だけで、同時要求は再認証を共有する。対象APIの認証検証は副作用の前に行われるため、この拒否だけが安全に再送できる。通信失敗・保存処理の失敗結果・部分成功は再送しない。元のフォームを閉じた場合やシーンを変更した場合も再送しない。再認証できなければ入力内容を保持し、編集URLの確認を案内する。

単体テストでは有効キーによる復旧、失効・不正キー、公開/internalモード、config読取失敗、同時要求、二重再送防止、フォーム終了を検証する。ブラウザテストでは実際のWAVからMP3を生成し、PNGと同時に添付して、失効後の新規保存・更新まで検証する。

## 検証結果

- 単体テスト445件、添付関連ブラウザテスト31件、音声ブラウザテスト全18件が成功（ブラウザテストの対象には重複あり）。既存の音声読込テストの100ms以内の中間状態は、複数の非同期アサーションを挟まず生成直後に取得するよう修正した。
- 音声ベンダーの固定版照合、差分チェックが成功。別レビューでも重大な指摘なし。
- テストGASの更新前7ファイルをバックアップし、反映直前にも他の変更がないことを確認。反映後7ファイルを読み戻してローカルと一致。公開 `/exec` は更新していない。
- 実際の `/dev` で、ブラウザ内の一時トークンを無効値にした状態から音声エディターが自動復旧。2秒の生成WAVをMP3へ変換し、PNGと同時添付した。
- 保存前にも無効な一時トークンを設定し、GASの `updateHotspot` 拒否 → `refreshEditToken` → `updateHotspot` 完了を実行ログで確認。保存後の写真は160pxで表示され、MP3は2.064秒として再生できた。
- 作成した検証用スポットと添付ファイルはアプリの削除APIで片付け、スポットの再読込でも残存しないことを確認。画面を再読込して一時的な検証状態を解除した。
