# ホットスポット添付写真アップロード設計

## 目的と採用方式

ホットスポットの新規追加・既存編集フォームから JPEG／PNG／WebP を選び、保存操作の一部として専用 Drive フォルダへ添付できるようにする。別の公開アップロード API は追加せず、既存の `saveHotspot`／`updateHotspot` に任意の `photoUpload` を渡す。

検討した方式は次の三つである。

1. 既存のシーン画像アップロード処理と `IMAGE_DRIVE_URL` 配下を共用する方式は、添付が scenes やシーン一覧へ混入し、削除対象の区別も弱くなるため採用しない。
2. 添付専用の先行アップロード API を追加する方式は、保存前キャンセルで孤立ファイルを作りやすく、要件にも反するため採用しない。
3. クライアントで画像を縮小・圧縮して保持し、ホットスポット保存時だけ既存 CRUD に同梱する方式を採用する。サーバーは通常入力を先に検証し、添付作成と info 保存を補償処理付きで一続きに扱う。

## クライアントの選択状態と UI

写真セレクトは `写真をアップロード…`、`（なし）`、既存写真の順に構築する。編集対象が既存の管理添付を参照している場合は、その ID を失わないため `現在のアップロード写真` という選択肢を `（なし）` の後へ補う。アップロード用の値は Drive ID と衝突しない予約値を使う。

非表示の file input は `accept` に JPEG／PNG／WebP だけを指定し、`capture` 属性は付けない。これによりスマートフォンでは撮影とライブラリ選択の双方を OS ピッカーへ委ねる。アップロード項目を選ぶ直前のセレクト値と処理済み添付状態を保持し、`cancel` イベントおよび focus 復帰の補助経路でピッカーキャンセルを検知して元へ戻す。

選択成功後は、処理後 Blob の Object URL をプレビューに使い、元ファイル名、元サイズ、処理後サイズ、変更、解除を表示する。変更に失敗またはキャンセルした場合は直前の選択とプレビューを残す。解除はアップロード状態を破棄して `（なし）` を選ぶ。フォームを閉じる、ページを離れる、保存成功でフォームを閉じる各経路は Object URL を revoke し、file input と一時データを初期化する。

保存までは `google.script.run` を呼ばない。保存 payload は既存写真なら `photoId`、新規添付なら `photoUpload` の一方だけを持つ。通信・サーバー失敗では既存フォームセッション、入力、処理済みファイル、プレビュー、仮マーカーを維持する。

## ブラウザ画像処理

元ファイルは実サイズ 20 MiB 以下、拡張子とブラウザ MIME が JPEG／PNG／WebP の対応関係に一致するものだけを受け付ける。先頭バイトも確認し、SVG、GIF、偽装拡張子を保存前に拒否する。

画像をデコードし、長辺が 2560 px を超える場合は縦横比を保って縮小する。JPEG は JPEG、WebP は WebP を第一候補として canvas から品質 0.85 で生成する。PNG は縮小不要かつ 6 MiB 以下なら元 Blob を維持し、それ以外は WebP、未対応ブラウザでは JPEG へ変換する。最初の生成物が 6 MiB を超える場合は品質と寸法を段階的に下げ、最終 Blob が 6 MiB 以下にならなければエラーにする。送信値には raw Base64、確定 MIME、表示用元ファイル名、元サイズ、処理後サイズを含める。

## 添付専用 Drive フォルダ

`HOTSPOT_PHOTO_FOLDER_ID` ScriptProperty を唯一の正式参照とする。値がある場合は Drive フォルダとして読めること、ID が一致すること、本体スプレッドシートと同じ親フォルダにあることを検証する。読めない、ファイルを指す、親が異なるなど正式 ID が壊れている場合はエラーにし、代替フォルダを作らない。

値がない場合だけ、ScriptLock 内で本体スプレッドシートの親フォルダへ `Hemisphere ホットスポット写真` を遅延作成し、その ID を ScriptProperties へ保存する。`IMAGE_DRIVE_URL`、フォルダ同期、scenes upsert は呼ばない。保存ファイル名はユーザー名を使わず、日時と UUID と検証済み MIME 由来の拡張子から一意に生成する。フォルダ ID は戻り値へ含めない。

## サーバー検証と保存契約

`photoUpload` は JPEG／PNG／WebP の厳密な MIME、対応する最終拡張子、Base64 形式、申告サイズ、元サイズ 20 MiB 以下、復号サイズ 6 MiB 以下を検証する。復号バイトは JPEG SOI、PNG 8-byte signature、RIFF/WEBP signature と照合する。MIME、拡張子、実バイトの三者が一致しない payload、GIF、SVG、空データは拒否する。

両 CRUD は次の順序を守る。

1. `assertEditToken_` を実行する。
2. Lock 内でラベル／ジャンプ、対象 scene、scene 種別、座標、URL、マーカー、既存 `photoId` とジャンプ先を検証する。
3. 更新では対象 hotspot 行と旧 `photoId` を確定する。
4. `photoId` と `photoUpload` の同時指定を拒否し、`photoUpload` 全体を検証する。
5. 必要な場合だけ専用フォルダと添付ファイルを作る。
6. info 行を追記または更新する。
7. info 保存失敗なら、その要求で作ったファイルをゴミ箱へ移して失敗を返す。

成功時は `id`、確定 `photoId` に加え、サーバーで正規化した hotspot オブジェクトを返す。クライアントはローカル payload ではなくこの hotspot を実マーカーへ反映する。

## 置換・削除後の孤立整理

更新で旧写真が変わった場合と hotspot 行削除後に、旧 `photoId` を整理候補にする。info 全行の写真列に同じ ID が残っていれば共有中として何もしない。参照がなく、正式添付フォルダ直下にあることを実 Drive の親で確認できたファイルだけをゴミ箱へ移す。scenes 登録画像、`IMAGE_DRIVE_URL` 配下の既存写真、別フォルダの Drive ファイルは削除しない。

info 更新・削除が完了した後の整理に失敗してもデータを巻き戻さず、`success: true`、`partialSuccess: true`、`warning`／`warnings` を返す。クライアントは成功マーカー更新後に警告トーストを出す。

## 公開写真取得

`getHotspotPhotoDataUri` は `{ fileId, hotspotId, photoId }` を受け、三値が完全一致する info 行が現在存在する場合だけ処理する。まず `fileId` が公開可能な登録 scene であることを検証し、次に写真が次のどちらかであることを検証する。

- scenes に登録され、設定済みルート内の実 Drive 親を持つ既存シーン画像。
- `HOTSPOT_PHOTO_FOLDER_ID` が指す正式添付フォルダ直下の JPEG／PNG／WebP。

任意 ID、別 hotspot の関連付け、削除済み行、登録されていないルート内ファイルは拒否する。成功時は owner 権限で Blob を読み、`data:` URI を返す。Drive URL とフォルダ ID は公開レスポンスや HTML に含めない。

## 回帰とテスト

Node テストでは、トークン検証前の副作用禁止、三者一致、サイズ、正式フォルダの一意作成と破損時 fail-closed、info 失敗 rollback、共有参照、管理対象判定、partial success、公開三値照合、scenes 非登録を Drive／Sheet の状態まで検証する。

Playwright ハーネスはサーバー確定 `photoId` を含む正規化応答を返せるようにし、セレクト順、選択／プレビュー／変更／解除、キャンセル復帰、保存前無通信、成功反映、失敗保持、新規／編集を確認する。ライト／ダーク、360／2D、PC／スマートフォン／800×360 の組み合わせでは保存・キャンセルの到達性、横オーバーフロー、重なり、runtime error がないことも検証する。

既存の仮マーカー、位置変更、操作 lock、通常写真選択、CRUD、一括入力、シーン保護、単一画像互換は既存テストを含む全 suite で回帰確認する。
