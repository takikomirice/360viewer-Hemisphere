# 読み込み改善の追加検証

2026-09-11、`ec80a43` を基準に、初期表示、フォルダ移動、低速回線の添付先読みを確認した。実測して改善を確認できたフォルダキャッシュ利用を採用し、初期表示の通信結合案は撤去した。

## 採用した変更

- public閲覧の `openSubfolder` は既存の `navigateToFolder(id, false)` を使う。サーバーの5分キャッシュが有効ならDrive一覧取得・scenes同期を繰り返さない。期限切れ・キャッシュ消失時は既存のロック付き同期へ進む。
- 編集時は引き続き強制同期する。「シーン一覧を更新」はルートを同期し、各子フォルダも次に開く際に一度強制同期する。失敗時は次回も再同期し、成功したフォルダだけキャッシュ利用に戻す。更新中に古い応答が届いても、新しい更新状態を消費しない。
- ブラウザーが接続を3Gと報告する場合、写真・音声の自動先読みを同時2件から1件に抑える。取得途中・取得済みのシーン間再利用と上限は維持する。通信量節約・2Gで自動先読みを行わない既存条件も維持する。回線情報のないブラウザーは従来どおり。これは競合を抑える変更であり、3G実機での表示時間短縮は未計測。

通常閲覧では外部から追加した画像の反映まで最大5分かかる場合がある。即時反映は「シーン一覧を更新」後、対象フォルダを開く。`folderCache=0` は毎回同期する比較用設定。

API・保存形式・権限検証は変更していない。キャッシュ命中時でも、現在のDrive上の親フォルダを確認する既存の範囲検証を通る。

## フォルダ一覧の実測

Windows Chrome、実際の `/dev`、同じ16件の設定済みルートに対して、サブフォルダ移動と同じ `navigateToFolder` APIを `true → false → true → false` の順に呼んだ。子フォルダの実データでの計測ではなく、同じ一覧APIの同期とキャッシュ取得の比較である。GAS往復からレスポンス到着までを計測し、シーン描画時間は含まない。全試行で件数16、エラーなし。

| 処理 | 1回目 | 2回目 |
|---|---:|---:|
| 毎回同期 | 4,426ms | 6,774ms |
| キャッシュ利用 | 2,536ms | 1,511ms |

平均は5,600msから約2,024ms。少数試行のため、端末やフォルダ規模全般の保証ではない。子フォルダの画面操作、手動更新、失敗後の再試行、範囲外への移動後の拒否は自動テストで別途確認する。

## 採用しなかった初期表示の通信結合

試作では既存の設定取得と最初のマーカー・方位情報取得を1回のGAS呼び出しにまとめた。往復は減るが、マーカー情報が返るまでブラウザーで画像を取得できず、現行の画像・マーカー並行取得の利点を失う。

各回、新しいアプリのタブを開き、アプリ初期化開始から最初のシーン表示完了までを計測した。外側の `/dev` のHTML取得・リダイレクト待ちは含まない。キャッシュなし条件は設定応答前に計測タブのCDP `Network.setCacheDisabled` を有効にした。Google側のキャッシュや回線の揺れは制御していない。

| 条件 | 結合試作 | 現行方式 |
|---|---:|---:|
| 画像キャッシュ無効・1 | 6,819ms | 7,168ms |
| 画像キャッシュ無効・2 | 6,224ms | 4,826ms |
| 画像キャッシュあり | 5,023ms | 4,169ms |

キャッシュ無効時の画像取得は512〜1,141ms、キャッシュありでは12〜16ms。結合試作が安定して優位とは言えなかったため、試作のサーバーAPI・クライアント分岐とも撤去した。最終版の初期表示は現行方式を維持する。試作の差分・計測ログはローカルの除外ディレクトリ `output/quality-audit/startup-loading/` に保存した。
