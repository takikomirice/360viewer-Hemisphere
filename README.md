# 360° Viewer - Hemisphere

Googleサイトに埋め込み可能な360度パノラマビューア（自作Thinglink風・GAS + Pannellum）。  
360度画像（または2D平面マップ）にホットスポット（解説マーカー）を追加し、閲覧できます。
探究学習向けの**はてなモード（フリップカード型クイズ）**にも対応しています。
**コンテナバインド型**（スプレッドシートに紐づいた GAS）で動作します。

## セットアップ手順

### ① Googleドライブに360度画像を準備

1. Googleドライブに正距円筒図法（equirectangular）形式の360度画像をアップロード  
   （または、後述の**写真アップロード機能**で編集モードから直接アップロード可能）
2. ファイル（またはフォルダ）を右クリック → **「共有」** → **「リンクを知っている全員」** が **「閲覧者」** になるよう設定
3. 「リンクをコピー」でURLを控えておく
   - **単一画像**: ファイルの共有リンク
   - **複数画像**: フォルダの共有リンク（直下の画像を一覧表示）
   - **写真アップロード機能を使う場合**: config の IMAGE_DRIVE_URL には**フォルダ**のURLを設定すること（ファイルURLは不可）

---

### ② Googleスプレッドシートを作成

1. [Google スプレッドシート](https://sheets.google.com) で新しいスプレッドシートを作成

---

### ③ スプレッドシートに Apps Script を追加

1. スプレッドシートのメニュー **「拡張機能」** → **「Apps Script」** をクリック
2. 左パネルの **「+ファイル」** から次の5ファイルを作成: `Code.js`, `index.html`, `styles.html`, `app.html`, `appsscript.json`
3. このリポジトリの各ファイルの内容を、同名ファイルに貼り付ける（`Code.js`, `index.html`, `styles.html`, `app.html`, `appsscript.json`）
   - **注意**: `index.html` が `<?!= include("styles") ?>` と `<?!= include("app") ?>` で `styles.html` と `app.html` を読み込むため、これら3ファイルはすべて必要です
4. （任意）一括入力用シート連携を使う場合: スプレッドシートで **「設定」** メニュー → **「一括入力用スプシを作成」** を実行すると自動作成・紐づけされる

---

### ④ 初期設定シートを生成し、画像URLを設定

1. スプレッドシートに戻り、**「設定」** メニュー → **「初期設定・更新」** を実行
2. **「config」** シートの **B2 セル** に、①でコピーしたGoogleドライブのURLを入力
3. 同時に `config`、`info`、`scenes` が不足分だけ作成・補修され、`EDIT_KEY` が未設定なら自動生成されます。通常、`EDIT_KEY` は手入力不要です。

---

### ⑤ Webアプリとしてデプロイ

1. Apps Script エディタに戻り、右上の **「デプロイ」** → **「新しいデプロイ」** をクリック
2. 設定:
   - **種類**: ウェブアプリ
   - **次のユーザーとして実行**: 自分（スプレッドシートへのアクセス権限が必要）
   - **アクセスできるユーザー**: Googleサイトで使う範囲に応じて選択
     - 校内のみ: `組織内の全員`
     - 一般公開: `全員`
3. **「デプロイ」** をクリック → 表示された **ウェブアプリURL**（末尾が `/exec` のURL）を控えておく
4. スプレッドシートに戻り、`config` シートの `WEB_APP_URL` へ、控えた `/exec` URLを直接入力する

### ⑥ 編集URL・公開URLを用意

編集キーは基本的に `config` シートの `EDIT_KEY` で管理します。初期設定時に `EDIT_KEY` が自動生成されるため、先生が Apps Script のスクリプト プロパティを触る必要はありません。

WebアプリURLの正式な参照元は `config` シートの `WEB_APP_URL` だけです。デプロイ済みWebアプリの `https://` で始まり `/exec` で終わるURLを直接貼り付けてください。空欄時の仮URLやサービスURLのfallbackは使用しません。

スプレッドシートの **「設定」** メニュー → **「編集用URLを生成・更新」** を実行すると、configの `WEB_APP_URL` と `EDIT_KEY` だけから編集URLを生成し、`EDIT_URL` セルへ保存します。初期設定では `EDIT_URL` を生成・更新しません。`WEB_APP_URL` または `EDIT_KEY` を直接編集すると古い `EDIT_URL` は空欄になるため、編集後にこのメニューを実行してください。`WEB_APP_URL` が空または有効な `/exec` URLでない場合も、古い `EDIT_URL` は空欄になります。

- **編集URL例**: `https://script.google.com/macros/s/xxxxx/exec?mode=edit&editKey=YOUR_EDIT_KEY`
- **公開URL例**: `https://script.google.com/macros/s/xxxxx/exec?mode=public&delivery=direct`
- 編集URLは Classroom などで共同編集者に共有する想定です。`EDIT_KEY` を変更しない限り、同じ編集URLを継続して使えます。
- `editKey` は個人認証ではなく共有鍵です。編集URLを知っている人は編集できます。
- Apps Script のスクリプト プロパティ `EDIT_KEY` は後方互換用にのみ残しています。configのキーが空欄なら初期設定時にその値を移行します。既存configキーと異なる旧キーは、configに保存済みの旧 `EDIT_URL` がそのキーを含む移行中だけ使えます。「編集用URLを生成・更新」後はconfigキーだけが有効です。configを読み取れない場合は旧キーへフォールバックせず、編集認証を拒否します。
- 共有URL、iframe、QRも `WEB_APP_URL` を元に作ります。`WEB_APP_URL` を変更したら、共有URL・QRもそのURLを元に更新されます。
- 6時間で切れるのは `EDIT_KEY` ではなく、一時的な編集トークンです。開きっぱなしで編集できなくなった場合は、同じ編集URLを再読み込みしてください。
- **「編集キーを再生成」** を実行すると `config` シートの `EDIT_KEY` が新しい値に変わり、古い編集URLと、そのキーで発行済みの一時編集トークンは直ちに使えなくなります。授業中の再生成には注意してください。
- 通常のWebアプリURLでは編集ボタンは表示されず、閲覧専用として開きます。
- public URL、iframe、QRには `editKey` を含めないでください。
- `mode=public` / `mode=internal` / modeなしでは編集トークンを発行しません。
- シーンの「プロパティを表示」はDrive URLや撮影情報を扱うため、画面表示だけでなくサーバー側でも有効な編集トークンを必須とします。通常URL・public・internalからの直接呼出しは拒否されます。
- 公開・埋め込みビューからブラウザコンソールで編集系APIを呼んでも、GAS側の `assertEditToken_()` により拒否されます。

画像配信方式は `delivery` パラメータで指定できます。未指定時は `direct` です。

- `delivery=direct`: Drive直リンクで表示する通常モード。最速で、学校内運用の標準です。
- `delivery=auto`: まずDrive直リンクで試し、失敗時のみBase64 fallbackを試す互換モードです。Googleサイト埋め込みやブラウザ相性に備える場合に使います。
- `delivery=base64`: 最初からBase64 Data URIを使う強制互換モードです。遅くなるため常用しないでください。

Base64は権限突破ではありません。GAS実行者が画像にアクセスできない場合は、Base64でも表示できません。

- **標準の公開URL例**: `https://script.google.com/macros/s/xxxxx/exec?mode=public&delivery=direct`
- **互換用公開URL例**: `https://script.google.com/macros/s/xxxxx/exec?mode=public&delivery=auto`
- **強制Base64公開URL例**: `https://script.google.com/macros/s/xxxxx/exec?mode=public&delivery=base64`

ビューア右上の **「共有」** ボタンから、公開用のURL、iframeコード、またはQRコードを作成できます。共有モーダルで生成されるURLは常に `mode=public` になり、編集用の `editKey` は含まれません。

- **URL共有**: Classroom、Googleスライド、チャットなどにURLをそのまま貼る場合に使います。
- **iframe共有**: GoogleサイトなどでHTML埋め込みを使う場合に使います。
- **QR共有**: スマホ閲覧用に、public URL のQRコードを画面内に表示します。編集URLや `editKey` はQRコードに含めません。
- **画像配信**: `delivery=direct / auto / base64` を選択できます。通常は `direct`、埋め込み先との相性問題がある場合は `auto`、最終手段として `base64` を使います。
- **画質**: 共有時には選択しません。共有URLは短く保ち、閲覧後に画面右上の画質切替ボタンで速度優先/高画質を変更できます。共有URLのデフォルトは速度優先です。
- **共有対象**:
  - **ホームから**: `scene`、`yaw`、`pitch` を含めず、`scenes` でホーム設定された画像から開始します。
  - **現在のシーンから**: フォルダモードで現在の `scene=<fileId>` を含めます。
  - **現在の視点から**: 360度ビューで現在の `scene=<fileId>`、`yaw`、`pitch` を含めます。2Dモードでは `yaw` / `pitch` は基本的に省略・無視されます。

QRコードは、共有モーダルの `delivery` と共有対象の設定に連動して更新されます。QRコードの下にはURL文字列を長く表示せず、public URLを内部的にQR化します。QRコード生成は外部QR生成APIに共有URLを送らず、ブラウザ内のSVG生成で完結します。

`scene=<fileId>` はルートのシーン一覧にある画像だけを初期表示対象にします。サブフォルダ内の画像IDは、今回の共有URL初期表示では探索せず、見つからない場合は従来どおりホーム画像に戻ります。

### 表示速度・キャッシュ

- フォルダ一覧は `scenes` 情報を結合した状態でサーバー側に短時間キャッシュされます。初期表示、一覧更新、サブフォルダを開く操作では対象フォルダを同期し、全サブフォルダを再帰走査しません。
- 画像アップロード、設定の変更、写真削除などの編集後と、自動登録、ホーム正規化、northOffset保存後は、関連するフォルダ一覧キャッシュを無効化します。
- public閲覧では、同一ページ内で一度取得したホットスポット取得結果をキャッシュし、同じシーンに戻ったときの再取得を減らします。
- `delivery=auto` は直リンク失敗時、または一定時間読み込みできない場合にBase64 fallbackを試します。`delivery=direct` はBase64 fallbackを行わない標準の最速モードです。
- Driveへ直接追加した画像は、ページ初期表示またはシーン一覧更新で `scenes` へ自動登録されます。表示が古い場合は、ページ再読み込みまたはシーン一覧更新を試してください。

### ⑦ Googleサイトに埋め込む

#### 方法A（URL埋め込み）

1. Googleサイトのページを編集モードで開く
2. ビューア右上の **「共有」** ボタンで **URL** を選択し、必要に応じて `delivery` と共有対象を選んでコピー
3. 右パネルの **「埋め込む」** → **「URLを埋め込む」** にURLを貼り付け
4. **「挿入」** → サイズを調整して保存

#### 方法B（iframe 埋め込み）

1. ビューアを開き、右上の **「共有」** ボタンをクリック
2. 形式で **iframe** を選択し、必要に応じて `delivery` と共有対象を選ぶ
3. 表示された iframe コードをコピー
4. Googleサイトで **「埋め込む」** → **「HTMLを埋め込む」** にコードを貼り付け

#### 方法C（QRコード）

1. ビューアを開き、右上の **「共有」** ボタンをクリック
2. 形式で **QR** を選択し、必要に応じて `delivery` と共有対象を選ぶ
3. 表示されたQRコードをスマホで読み取るか、**「URLをコピー」** ボタンでpublic URLをコピーして配布する
4. QRコードは `mode=public` の閲覧URL用です。編集URLや `editKey` は含めません。

## 使い方

### 閲覧モード（生徒向け）

- 画面をドラッグして360度ビューを操作（2D平面マップはスクロール・ズームで操作）
- マーカーをクリックするとラベル・説明・リンク・写真などが表示される（アイコンが「クイズ」のマーカーはフリップカードが開く）
- 複数画像がある場合、トップバー左のシーン一覧で他のパノラマ／2Dマップに移動できる
- ホットスポットに「ジャンプ先」が設定されている場合、クリックで別シーンへ遷移できる
- **写真右上のボタン**:
  - **全画面**: フルスクリーン表示
  - **ホーム**: `scenes` でホーム設定されたシーンへジャンプ（フォルダモード時のみ表示）
  - **画質切り替え**: 低負荷（fast）⇔ 高画質（high）をトグル
  - **ジャイロ**（モバイルのみ）: スマホを傾けて視点を操作
- **共有**: 右上の「共有」ボタンで、公開用URL、Googleサイト等に貼る iframe コード、スマホ閲覧用QRコードを生成できる。共有URLとQRコードには `editKey` を含めない
- **URLパラメータ**: `?mode=internal` / `?mode=public` でトップバー非表示（埋め込み向け）、`?quality=high` / `?quality=fast` で初期画質、`?delivery=direct|auto|base64` で画像配信方式、`?scene=<fileId>` で初期シーン、`?yaw=...&pitch=...` で360度ビューの初期視点を指定可能
- `?mode=public` / `?mode=internal` / modeなしでは編集トークンを発行しないため、ブラウザコンソールから保存・更新・削除・アップロード系のGAS関数を直接呼んでも実行できません。この仕組みは個人ごとの認証・権限制御ではなく、公開ビューからの編集操作を防ぐためのものです。
- 通常のWebアプリURL（`mode` なし）で開いた場合は閲覧専用として開き、編集ボタンは表示されません。編集するには **「編集用URLを生成・更新」** でconfigの `EDIT_URL` に保存された `mode=edit&editKey=...` のURLを開いてください。`mode=edit` なのに編集できない場合は、config シートの `EDIT_KEY` または URL の `editKey` を確認してください。

### スマホ閲覧

スマホやタブレットでは `mode=public` の共有URLを使う public閲覧モードを想定しています。編集はPC推奨です。

- スマホ幅の public閲覧では、シーン一覧は下部の「シーンを選ぶ」UIから展開するボトムシート形式で表示されます。
- ホットスポットの詳細は下から出るカードとして表示され、長い説明文や写真はカード内でスクロールできます。
- ジャイロ操作に対応しており、初回表示時に短い案内を表示します。
- 2D平面マップもスマホ幅で表示できるよう、下部シーンUIと重なりすぎない配置にしています。
- 共有モーダルのQR形式で、スマホ閲覧用の `mode=public` URLをQRコードとして表示できます。編集URLのQR化は想定していません。

### 編集モード（教員向け）

1. スプレッドシートの **「設定」** → **「編集用URLを生成・更新」** を実行し、configの `EDIT_URL` に保存された `?mode=edit&editKey=...` の編集URLでビューアを開く
2. 右上の **「編集モード」** ボタンをクリック
3. 画面が黄色のハイライト枠に切り替わる
4. 解説を追加したい場所をクリック
5. 入力項目を設定して **「保存する」** をクリック:
   - **ラベル**（通常マーカーは必須。ジャンプモードではラベル欄を非表示・無効化し、新規は空欄のまま保存。既存ジャンプの保存済みラベルは削除しない）
   - **詳細説明**
   - **リンク**: 外部URL（https://...）
   - **マーカー見た目**: 形（丸/四角/菱形）、12色、アイコン（情報/写真/リンク/Wi-Fi/**クイズ**/観察/注意/目的地/動物/葉っぱ/花/史跡）
   - **写真**（フォルダモード時のみ）: 同フォルダ内の画像を紐付け、ホットスポット表示時に表示
   - **ジャンプ先シーン**（フォルダモード時のみ・必須）: クリックで別のシーンへ移動。閲覧時は最新のジャンプ先シーン名を表示し、対象が見つからない場合だけ保存済みラベル、IDの順に表示する
6. 既存のホットスポット: **右クリック**で「編集」「移動」「削除」メニュー表示
7. **フォルダモード時**: シーン一覧の画像を**右クリック** → 「設定の変更」（名前・種別・北方向補正を1回で保存）、「ホームに設定」、「プロパティを表示」、「写真を削除」。名前変更では元の画像拡張子を維持する。保存済みホットスポットがある場合、座標形式が異なるため360↔2Dの種別変更は、先にホットスポットを削除するまで拒否される
8. **写真をアップロード**: シーン一覧上の **「⬆ 写真をアップロード」** ボタンから、360°パノラマまたは2D平面マップを直接Googleドライブに追加できる（config でフォルダURLを設定済みであること）
9. **シーン一覧の更新**: フォルダモード時、シーン一覧左端の **更新ボタン（↻）** で画像一覧を再取得できる
10. **一括入力用シート連携**（フォルダモード時）: 「入力用スプシのリストを更新」「入力用スプシを一括取り込み」で、一括入力用シートからホットスポットを登録できる（[詳細](#一括入力用シート連携)）

シーン一覧、設定モーダル、写真・ジャンプ先選択肢、ジャンプツールチップでは対応する画像拡張子（jpg/jpeg/png/gif/webp）を表示しません。Drive上の正式名と `scenes` の保存値は拡張子付きのまま維持し、「プロパティを表示」では正式名を確認できます。

Drive名が `=` で始まる場合も、`scenes` で数式に変換せず表示名の文字列として保存します。

マーカー値の一覧:

- 形状ID: circle/square/diamond（旧 `star` は読込時に `circle` へフォールバック）
- 色ID: blue/cyan/teal/green/lime/yellow/orange/red/pink/purple/gray/white
- アイコンID（新規選択）: info/photo/link/wifi/quiz/eye/warning/flag/animal/leaf/flower/historic

旧 `star` は読み込み表示と編集フォーム復元時だけ `circle` として扱い、既存の `info` シートやlocalStorageを読み込みだけで自動変更しません。旧 `video` / `audio` は新規選択肢には表示しませんが、既存マーカーの表示・編集・保存では元の値とSVGを維持します。動画・音声の再生機能は追加されません。既存の `quiz` だけがフリップカードを開きます。

ホットスポットの「移動」を開始すると、元マーカーが半透明になり、同じ形・色・アイコンの仮マーカーがカーソルまたはタッチ位置へ追従します。360画像は単純クリック／短いタップをYaw・Pitchへ変換し、2D画像は画像内のX・Y百分率へ変換します。パノラマのドラッグ、画像外の操作、Esc、シーン変更、編集モード終了では確定せず、保存成功時だけ実マーカーが移動します。ホットスポットの保存・更新・削除要求中は同一シーンの「設定の変更」を待機し、送信後に種別が変わった場合はサーバーも座標保存を拒否します。移動の保存要求を送信した後は、シートと画面の競合を避けるため、応答が返るまで同じマーカーの編集・削除・再移動とシーン切替を待機します。

### はてなモード（フリップカード型クイズ）

マーカーのアイコンを **「クイズ」** に設定すると、クリック時に通常のポップアップではなくフリップカードが表示されます。
探究学習や現地調査で「問い→答え」を対話的に確認するシーンに活用できます。

**設定方法:**

1. 編集モードでホットスポットを追加・編集
2. 「マーカー見た目」パネルで **アイコン = クイズ** を選択
3. **詳細説明** に `問題文|答え` の形式で入力（`|` でパイプ区切り）
   - 例: `この橋が架けられたのは何年ですか？|1954年（昭和29年）`
   - `|` 以降を省略した場合は「答えが設定されていません」と表示される
4. （任意）**リンク** に URL を設定すると、答え面に「さらに詳しく」リンクが表示される

**生徒の操作:**

- マーカーをクリック → 問題面のカードが開く
- カードをクリック → 裏返って答えが表示される（再クリックで問題面に戻る）
- `×` ボタン、またはカード外の暗転エリアをクリックで閉じる

### 2D平面マップについて

- 画像種別は `scenes` の `2D` / `360` を正式な参照元とする
- Driveへ直接追加した未登録画像だけ、ファイル名内の `[2D]` を初回同期時に `2D` へ移行する。登録後にタグを追加・削除しても種別は変わらず、既存タグも自動削除しない
- 写真アップロード時の「2D平面マップ」選択は `scenes` へ直接保存され、ファイル名へ `[2D]` を自動付与しない
- 2Dモードでもホットスポット（ラベル・説明・リンク・ジャンプ先など）は同様に利用可能

### ホームシーン

- ホーム設定は `scenes` を正式な参照元とし、ルートフォルダ直下で最大1件へ正規化する
- 未登録画像だけ、ファイル名内の `[HOME]` を初回同期時のホーム候補として扱う。登録後の名前変更ではホーム設定を変えず、タグも自動削除しない
- 既存の有効なホーム、今回の新規 `[HOME]` 画像、表示順が最初の画像、の順で選ぶ

### フォルダモードのサブフォルダ

- config にフォルダURLを設定した場合、サブフォルダ内の画像も階層的に表示される
- サイドバーでフォルダをクリックすると、configで設定したルート配下であることを親方向だけに確認し、そのフォルダ直下だけをDriveと `scenes` で同期して表示する。「← 戻る」で上位フォルダに戻れ、全サブフォルダは再帰走査しない

### Driveとscenesの同期・部分成功

- 同期でDrive一覧に見つからないだけの画像は、`scenes` や `info` から削除しない。画像とホットスポットを削除するのは、編集画面で明示削除し、Driveのゴミ箱移動が成功した場合だけ
- アップロード後に `scenes` 登録だけ失敗してもDriveファイルは削除せず、画面へ部分成功を表示する。次の一覧同期で未登録画像として再登録できる
- 名前変更はDrive成功後に `scenes` の表示名を更新する。後段だけ失敗した場合は部分成功を表示し、Drive更新日時を基に次回同期で表示名を修復する
- 明示削除でDrive成功後の `info` / `scenes` 整理に失敗した場合も、残った状態を警告として表示する
- Drive・シート更新後にキャッシュ無効化だけ失敗した場合も、成功済みの状態を隠さず部分成功として警告する
- 同じDriveファイルをフォルダ間で移動した場合は、ファイルIDが同じ `scenes` 行の親IDを更新し、移動前と移動後の両フォルダのキャッシュを重複排除して無効化する。無効化だけ失敗してもscenes更新は維持し、対象フォルダIDをログと警告へ残す

## 一括入力用シート連携

スプレッドシートでホットスポット情報を入力し、編集モードから一括取り込みできる機能です。

### 準備

1. 一括入力用スプレッドシートを用意
   - **メニューから作成**: **「設定」** → **「一括入力用スプシを作成」** を実行すると、正式IDが未設定の場合だけコンテナスプレッドシートと同じフォルダ内に作成される。ヘッダー行・列幅・入力規則（フォルダ設定済みなら）も自動設定される
   - 正式な紐づけ情報は ScriptProperties の `STUDENT_SHEET_ID` だけ。作成済みの有効なIDがあれば重複作成せず、同じスプシを検証・更新する
   - `config` の `STUDENT_SHEET_URL` は正式IDから取得したURLの表示欄。ここを書き換えても紐づき先は変わらず、作成・更新・取込時に正式URLへ修復される
2. 一括入力用シートに次の列構成でテンプレートを用意（1行目はヘッダー）:

| 列 | 内容 |
| -- | -- |
| A | No（行番号など、任意） |
| B | 対象シーン（画像名） |
| C | ラベル |
| D | 説明 |
| E | リンクURL |
| F | 写真（同フォルダ内の画像名） |
| G | ジャンプ先（画像名） |
| H | 状態（取り込み済みは「済」） |

### 編集モードでの操作

- **入力用スプシのリストを更新**: ビューア編集モードのサイドバーから実行。B列・F列・G列に config のフォルダ内画像名のプルダウンを設定する（スプレッドシートの **「設定」** → **「一括入力用スプシを更新」** からも実行可能）
- **入力用スプシを一括取り込み**: H列が「済」でない行のうち、対象・写真・ジャンプ先の画像名が一意に解決できる行だけをinfoシートへ追加し、H列を「済」に更新。通常マーカーはラベル必須、ジャンプ先がある行は空ラベルをそのまま保持する。画像名が存在しない／同名で曖昧／通常ラベルが空の行は取り込まず、H列も未処理のまま残す

### 設定メニュー（一括入力用）

| メニュー項目 | 内容 |
| -- | -- |
| 一括入力用スプシを作成 | 正式IDがなければ新規作成し、あれば既存スプシを検証する |
| 一括入力用スプシを更新 | 正式IDのURL、空ヘッダー、B・F・G列のプルダウンを更新する |
| 一括入力データを取り込む | 正式IDの未処理データを取り込み、件数とスキップ件数をtoast表示する |

※ フォルダモードかつ `IMAGE_DRIVE_URL` にフォルダURLが設定されている場合のみ利用可能。  
※ 一括取り込み時は Pitch/Yaw が 0 になるため、必要に応じて編集モードでホットスポットの位置を調整してください。

## スプレッドシートのシート構成

### config シート（設定）

| 列 | 内容 |
| -- | -- |
| A | 設定項目（IMAGE_DRIVE_URL など） |
| B | 値（GoogleドライブのURL：単一ファイルまたはフォルダ。フォルダ指定でサブフォルダ・複数画像対応） |
| C | 説明 |

基本項目は次の順で配置されます。既存のその他設定はこの後ろに保持されます。

1. `IMAGE_DRIVE_URL`
2. `STUDENT_SHEET_URL`
3. `WEB_APP_URL`
4. `EDIT_URL`
5. `EDIT_KEY`

### scenes シート（画像単位設定）

| 列 | 内容 |
| -- | -- |
| A | DriveファイルID（主キー） |
| B | 表示名 |
| C | 親フォルダID |
| D | 種別 |
| E | ホーム設定 |
| F | 表示順 |
| G | northOffset |
| H | northOffset取得元（`xmp` / `none` / `manual`） |
| I | Drive更新日時 |
| J | scenes行の更新日時 |

旧 `config` の `NORTH_<DriveファイルID>` は初期設定の再実行時に `scenes` へ移行されます。数値と `NONE` は保存結果を確認できた行だけ削除し、不正値・移行失敗・manual値との衝突は `config` に残します。

フォルダモードでは、表示対象フォルダのDrive画像をファイルIDで照合し、未登録画像だけを `scenes` の末尾へ一括登録します。既存行の種別・ホーム・表示順・northOffsetはファイル名タグで上書きしません。Drive一覧の欠落は削除扱いにせず、`info` を同期処理から変更しません。

公開画面のnorthOffset取得は、登録済み `scenes` 行・設定ルート配下の親フォルダ・種別 `360`・JPEGの全条件を満たす画像だけを対象とします。未登録、ルート外、`2D`、JPEG以外ではDrive BlobやXMPを読まず `null` とし、`scenes` 行も作成しません。単一画像モードではconfigで明示指定したファイルIDとの一致時だけ取得し、`2D` 表示では既存値があっても使いません。

### info シート（ホットスポット）

| 列 | 内容 |
| -- | -- |
| A | 保存日時 |
| B | 画像ID |
| C | ラベル |
| D | 説明 |
| E | リンクURL |
| F | Pitch（上下角度） |
| G | Yaw（左右角度） |
| H | 形状（circle/square/diamond） |
| I | 色（blue/cyan/teal/green/lime/yellow/orange/red/pink/purple/gray/white） |
| J | アイコン（新規12種、または旧データ互換の video/audio） |
| K | 写真ID（GoogleドライブのファイルID、任意） |
| L | ジャンプ先ID（別シーンへの遷移先画像ID、任意） |
| M | ホットスポットID |

`config`、`info`、`scenes` シートは、**「初期設定」** メニュー → **「初期設定シートを生成」** で作成・補修。
`info` は `saveHotspot` 初回実行時にも自動作成されます。  
旧スキーマのシートには、初回アクセス時にマイグレーションが自動適用されます。
旧データの形状 `star` は表示時に `circle` へ正規化しますが、読み込みだけでシートを自動更新しません。編集して保存した場合は `circle` として保存されます。

## トラブルシューティング

| 症状 | 確認事項 |
| -- | -- |
| パノラマ画像が表示されない | Driveの共有設定が「リンクを知っている全員」になっているか、config シート B2 に URL が入力されているか確認 |
| 保存できない | コンテナバインド型であること、スクリプトの実行権限を再確認 |
| Googleサイトに埋め込めない | デプロイ時の「アクセスできるユーザー」設定を確認 |
| ホットスポットが表示されない | スプレッドシートのシート名が `info` か確認 |
| 写真アップロードが失敗する | config の IMAGE_DRIVE_URL に**フォルダ**のURLを設定しているか確認（ファイルURLは不可） |
| 一括入力用シート連携が使えない | ScriptProperties の `STUDENT_SHEET_ID` が有効か、IMAGE_DRIVE_URL がフォルダ URL か、一括入力用シートに編集権限があるか確認。「設定」→「一括入力用スプシを作成」は有効な既存IDを再利用する |
| ジャイロが使えない／表示されない | スマートフォン・タブレットのみ対応。HTTPS 環境であること、ブラウザが DeviceOrientation をサポートしていること、ユーザー許可が必要な場合あり |
| ホームボタンが表示されない | フォルダモード（IMAGE_DRIVE_URL にフォルダURLを設定）であること、画像が1件以上あることを確認 |

### 画像配信方式について

標準では `delivery=direct` として、`https://lh3.googleusercontent.com/d/{fileId}=w4096` または `=s0` を使った直接URLで画像を配信しています。
これは軽量で高速ですが、Google の非公式エンドポイントのため、Googleの仕様変更や埋め込み先・ブラウザ相性により表示できない可能性があります。

**画像が表示されない場合**は、まず `delivery=auto` を試してください。直リンクで失敗した場合のみ、GASが画像をBase64 Data URIに変換して再表示を試みます。
それでも表示できない場合の最終手段として `delivery=base64` を使えますが、読み込みが遅くなるため常用は避けてください。

Base64は権限突破ではありません。GAS実行者が対象画像にアクセスできない場合、`delivery=auto` や `delivery=base64` でも表示できません。
