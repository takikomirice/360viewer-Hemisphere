# シート基盤改善・第3段階 設計

## 目的と範囲

第1・第2段階の `scenes` を正式な画像単位設定として使い、編集画面から種別、northOffset、ホームを安全に変更できるようにする。アップロード時ホーム指定、scenes入力補助、軽量な `onOpen` メニュー整理も同じ段階で行う。表示順変更、独自UUID、再帰一括同期、行自動削除、info構造変更は行わない。

## 採用する構成

公開サーバーAPIは `getSceneSettings(payload)`、`updateSceneSettings(payload)`、`setHomeScene(payload)` の3責務に分け、すべて先頭で `assertEditToken_()` を実行する。共通の `getEditableSceneContext_()` は、登録済みscenes行、設定済みルート、行の親フォルダ、実Driveファイルの親、画像MIME、Drive ID一致を検証する。未登録、重複、ルート外、親不一致、画像以外は書込前に拒否する。

内部ホーム処理はトークン検証を持たず、公開APIとアップロード後処理からだけ呼ぶ。Lock内でルート直下行を一括読込し、対象をTRUE、同じルート直下の旧ホームだけをFALSEへ更新する。サブフォルダ行とinfoは変更しない。

検討した代替は、全設定を一つのAPIへ集約する方式、保存後に必ずフォルダforce refreshする方式、アップロード同期overrideへホーム候補を混ぜる方式である。前者は認可とエラー責務が曖昧になり、後二者は不要なDrive同期または既存ホーム優先ロジックとの競合を生むため採用しない。

## シーン設定とnorthOffset

クライアントへ返すsceneは、ID、表示名、親ID、種別、ホーム、表示順、northOffset、取得元、設定モード、ルート直下か、MIME、更新日時を正規化する。northOffset設定モードは `manual`、`none`、それ以外（空欄・`xmp`）を `auto` として返す。

`updateSceneSettings` は種別を `360` / `2D` に限定する。2Dへの変更はnorthOffset列を変更せず、公開表示の既存2D拒否を維持する。360でnorthOffsetモードが指定された場合は次の通り更新する。

- `auto`: 値と取得元を空欄にし、次回表示でJPEG XMPを再取得する。
- `manual`: 0以上360未満の有限数を保存し、取得元を `manual` にする。
- `none`: 値を空欄、取得元を `none` にし、再解析を止める。

編集者による明示変更だけは既存manual保護を解除できるフラグを内部upsertへ渡す。公開XMP経路は従来どおりmanualを上書きできない。

## ホームとアップロード

ホーム対象は設定ルート直下に実在する登録済み画像だけとする。360 / 2Dは問わない。同じホームの再指定は書込なしで成功する。更新後はルートキャッシュを無効化し、失敗時はホーム更新を維持した部分成功を返す。

アップロードpayloadへ `setAsHome` を追加する。ルート以外でTRUEならDrive作成前に拒否する。Drive作成、scenes同期、内部ホーム変更、キャッシュ処理の順に進め、ホーム段階だけ失敗してもDriveファイルとscenes行を残し、`partialSuccess` と警告を返す。複数ファイル選択時はホームチェックを無効にし、単一ファイルだけを対象とする。

## scenes入力補助とメニュー

scenes補修時に既存値を変更せず、データ検証だけを適用する。種別は `360` / `2D`、ホームはチェックボックス、取得元は空欄 / `xmp` / `manual` / `none`、northOffsetは空欄または0以上360未満の数値とする。シート保護は追加しない。

`onOpen` は `Hemisphere` 親メニューと「初期設定」「一括入力」サブメニューの生成だけを行う。一括取込用のメニューラッパーは既存の内部取込処理を再利用し、結果をダイアログ表示する。

## クライアントUI

右クリックメニューへ「シーン設定」「ホームに設定」を追加する。新規編集操作は有効な編集トークンと編集モードを要求する。ホームはルート直下かつ未ホーム時だけ有効にする。

設定モーダルは参照名、種別、northOffset 3モード、手動値、保存、キャンセルを持つ。背景クリックとEscで閉じ、保存中は閉じず二重送信を防ぐ。失敗時は入力を残す。2D選択時とmanual以外では手動欄を無効化する。閉じた後は起点ボタンへフォーカスを戻す。

保存成功時は正規化sceneを `allImages` に反映し、サイドバーとホームIDを更新する。現在シーンならホットスポットキャッシュを消し、360のままの変更だけ現在Yaw/Pitchを保持して再読込する。2D↔360では不適切な視点を引き継がず、既存 `loadScene` のviewer破棄・2D表示切替・ローディング解除を使う。ホーム変更は現在表示を移動しない。

## エラーとテスト

トークン不正はDrive/Sheet参照前に例外で拒否する。対象・入力不正は `success:false` と具体的なエラーを返す。キャッシュだけの失敗は成功済みシート更新を維持し、`partialSuccess`、warning、ログで表す。

テストはGASモックによるAPI動作、入力境界、Lock、キャッシュ、アップロード部分成功、scenesデータ検証、menu-only `onOpen` を検証する。UIはDOM構造と主要関数の静的検査、純粋ローカル更新ヘルパーのVMテストで、トークンpayload、二重送信、Esc/背景、2D無効化、再読込を確認する。最後に全回帰を実行し、成功後だけ3担当の読み取り専用レビューを並列実施する。
