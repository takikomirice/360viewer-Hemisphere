# シート基盤 第4段階A 完成設計

## 目的と制約

`v2.0.0` に実装済みの第4段階B（3形状、12色、10アイコン、旧 `star` の読込フォールバック、360/2D移動プレビュー、Pointer Events、RAF追従、キャンセル・復旧・stale応答対策）を変更・再実装せず、第4段階Aの未反映部分を完成させる。

実装中は単一エージェントで進め、コミット、push、PR作成は行わない。全テスト成功後だけ、最大3つの読み取り専用レビューを並列実施する。

## 採用アプローチ

既存のApps Script／単一クライアント構造を維持しながら、次の4つの責務を共通処理へ集約する。

1. config直接入力だけを使うEDIT_URL生成・消去
2. ScriptPropertiesだけを正本とする一括入力用スプシ参照
3. 名前・種別・northOffsetを原子的に扱うシーン設定保存
4. 保存名を変えずに表示だけ整える画像表示名正規化

既存関数へ個別の条件を足すだけの案は、`ScriptApp`フォールバックやconfig URL採用経路が残る危険がある。別ファイルへの全面分割は現行のApps Script配信構造に対して変更が大きい。このため、既存ファイル内で責務境界を明確にする限定的リファクタリングを採用する。

## EDIT_URLとメニュー

`WEB_APP_URL` はconfigの直接入力だけを正式な参照元とし、クエリとハッシュを除いた有効な `/exec` URLだけを受理する。`ScriptApp.getService().getUrl()`、入力ダイアログ、仮URL、表示ダイアログを削除する。

`setupSheets()` はconfigの不足行を補修し、空の `EDIT_KEY` を生成するだけにする。既存 `EDIT_URL` は変更せず、完了文にも更新を示さない。

明示メニュー操作は、同じconfigスナップショットの `WEB_APP_URL` と `EDIT_KEY` だけから次を保存する。

```text
<normalized /exec URL>?mode=edit&editKey=<encoded key>
```

URLが空または不正なら、古い `EDIT_URL` を必ず空にしてtoastで理由を通知する。キーが空ならこの操作の中で生成してよい。キー再生成も同じ明示更新処理を使い、URLが不正なら空欄化する。既存のScriptProperties `EDIT_KEY` が有効な場合に同時更新するfail-closed契約は維持する。

`onEdit(e)` は、編集対象が `config` シートかつキー列が `WEB_APP_URL` または `EDIT_KEY` の行に交差した場合だけ `EDIT_URL` セルを空にする。値の再生成、Drive、scenes、XMP、一括入力用スプシへのアクセスは行わない。

`onOpen()` はメニュー生成だけを行い、トップレベル `設定` に次の順でフラット配置する。

1. 初期設定・更新
2. separator
3. 編集用URLを生成・更新
4. 編集キーを再生成
5. separator
6. 一括入力用スプシを作成
7. 一括入力用スプシを更新
8. 一括入力データを取り込む

## 一括入力用スプシの正本

正式な紐づけはScriptPropertiesの `STUDENT_SHEET_ID` だけとする。configの `STUDENT_SHEET_URL` は現在の正式IDから導いた表示・確認欄であり、入力値からIDを採用しない。

共通コンテキスト取得は次の順で動作する。

1. ScriptPropertiesからIDを取得する
2. IDがなければ未紐づけとして停止する
3. `SpreadsheetApp.openById` で正式スプシを開く
4. 対象シートとヘッダーを検証し、指定時だけ空ヘッダーを補修する
5. 正式スプシのURLをconfigへ再出力する

メニュー作成は有効な既存IDを最初に検証する。開ける既存スプシがあれば重複作成せず、URLと必要な入力規則を修復してtoastする。IDがない場合だけ、本体スプシと同じ親フォルダに新規作成し、ヘッダー、列幅、固定行、入力規則を設定してからScriptPropertiesへID、configへURLを保存する。Webアプリ公開関数 `createStudentSheet(payload)` は削除し、作成処理は末尾 `_` の内部関数だけにする。

更新と取込は必ず同じ正式IDコンテキストを使う。更新は空ヘッダーと入力規則だけを補修し、既存入力行を保持する。取込は既存の処理済み状態、未処理行、スキップ判定を維持する。メニュー結果はすべてSpreadsheet toastで通知する。

## 設定の変更と名前更新

シーン右クリックメニューから独立した名前変更を削除し、先頭項目を `設定の変更` とする。設定モーダルも同名にし、参照表示をラベル `名前` の編集可能入力へ変える。クライアントの独立 `requestSceneRename` と `.renameImageFile(...)` 呼出しは削除する。

表示する初期値は、Drive名またはscenes表示名から対応画像拡張子だけを除いたものとする。保存前に前後空白、空欄、制御文字、拡張子を検証する。元ファイルの最終拡張子を維持し、同じ拡張子の入力は一度だけ残し、異なる拡張子は拒否する。元拡張子はMIMEタイプと一致していなければ更新を拒否する。

サーバー更新順序は次とする。

1. 編集トークン検証
2. 対象sceneとDriveファイルの検証
3. 名前、MIME/拡張子、種別、northOffsetの全入力検証
4. Lock取得後、同じ対象を再検証
5. 名前が変わる場合だけDrive `setName`
6. scenesの `displayName`、種別、northOffsetを一度に更新
7. フォルダ一覧キャッシュを無効化
8. 正規化済みsceneを返す

Drive名変更が失敗した場合はscenesを変更しない。Drive成功後のscenes失敗は `success: true, partialSuccess: true, driveUpdated: true, sceneUpdated: false` とし、次回Drive同期で修復可能な警告を返す。名前変更がない場合はDrive `setName` を呼ばない。独立公開関数 `renameImageFile` はクライアントから到達不能にし、重複実装を避けられない場合は削除する。

## 表示名とジャンプUI

クライアント共通関数は文字列末尾の `.jpg`、`.jpeg`、`.png`、`.gif`、`.webp` だけを大文字小文字を区別せず一度除去する。Drive名やscenes保存値は変更しない。シーン一覧、設定モーダル、写真選択肢、ジャンプ先選択肢、ジャンプツールチップ、ホーム関連表示へ適用する。プロパティ画面は正式な拡張子付きDrive名を維持する。

ジャンプモードではラベル欄を非表示かつ無効にし、新規作成時は空欄を維持する。編集時の既存ラベル値は消去しない。説明文として「閲覧時にはジャンプ先のシーン名が表示されます」を示し、ジャンプ先を必須にする。通常マーカーは従来どおりラベル必須とする。

ジャンプツールチップは、最新の `allImages` に存在する対象名を表示用共通関数へ通す。対象が見つからない場合だけ、保存済みラベル、`jumpSceneId` の順にフォールバックする。360と2Dの双方から保存済みラベルを渡す。

## エラー処理と整合性

- 明示的な生成以外ではEDIT_URLを作らず、入力変更時は古いURLを残さない。
- 正式な一括入力用スプシIDをconfig入力で上書きしない。
- 設定保存は全入力検証後に副作用を開始する。
- Lock前後の検証で、古いsceneスナップショットによる上書きを防ぐ。
- Driveだけ成功した部分成功を隠さず、クライアントのローカル表示も返却sceneに合わせる。
- 第4段階Bのホットスポット状態機械・カタログ・描画経路には必要最小限のラベル引数追加以外の変更を加えない。

## テスト戦略

既存のNode VMテストと静的契約テストを拡張し、実装前に失敗を確認する。

- EDIT_URL: setup時非生成、config限定、`/exec`検証、明示生成、エラー時消去、toast、onEdit、キー再生成
- メニュー: `設定`、7項目、順序、separator 2個、旧項目・サブメニュー不在
- 一括入力: ScriptProperties正本、config非採用、重複作成防止、公開作成API不在、URL修復、行保持
- シーン設定: 名前入力、拡張子規則、MIME整合、Drive失敗時無変更、scenes失敗時部分成功、種別・northOffset同時保存、名前不変時Drive未呼出し
- 表示名: 複数ドット・大文字拡張子、一覧・選択肢・ツールチップ、プロパティ正式名
- ジャンプ: 空ラベル保存、通常ラベル必須、ジャンプ先必須、既存ラベル保持、最新名とフォールバック
- 第4段階B: 3形状、12色、10アイコン、`star`、360/2D移動、RAF、キャンセル、復旧、stale応答

実装後に `node --check Code.js` と全 `node --test tests/*.test.js` を実行する。全成功後、指定分野A/B/Cを読み取り専用でレビューし、再現またはコード上で確認できる指摘だけ、先に失敗テストを追加して修正する。
