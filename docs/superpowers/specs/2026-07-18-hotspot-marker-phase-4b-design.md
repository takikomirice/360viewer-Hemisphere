# ホットスポットマーカー第4段階B 設計

## 目的と範囲

既存のホットスポット保存形式を維持したまま、選択可能な形状を3種類、色を12種類、アイコンを10種類へ整理する。旧 `star` はシートやブラウザ保存値を書き換えず、読み込み時だけ `circle` として扱う。動画・音声プレイヤーや外部アイコン依存は追加しない。

第4段階Aの前提確認では、空ラベルのジャンプマーカーを `loadHotspots`、`saveHotspot`、`updateHotspot` が一貫して扱う契約が現コードに不足している。第4段階Bの移動要件がこの契約に依存するため、同じ変更で先に補修する。

## 値カタログと正規化

- 形状: `circle`, `square`, `diamond`
- 色: `blue`, `cyan`, `teal`, `green`, `lime`, `yellow`, `orange`, `red`, `pink`, `purple`, `gray`, `white`
- アイコン: `info`, `photo`, `video`, `audio`, `link`, `wifi`, `quiz`, `eye`, `warning`, `flag`
- 既定値: `circle`, `blue`, `info`

サーバーは許可配列を正本として保存値と読込値を正規化する。クライアントはラベルマップを許可値の正本として、UI、localStorage、編集値、360描画、2D描画を同じ正規化関数へ通す。不正値と `star` は既定値へ戻す。読込正規化は `info` シートへ書き戻さない。

## マーカー描画

各アイコンは `viewBox="0 0 24 24"`、共通の線幅と線端を持つインラインSVG断片として一元管理する。360のPannellumマーカー、2Dマーカー、設定プレビュー、移動プレビューはいずれも同じ `applyMarkerClasses` と `applyMarkerIconClass` を通す。

色はCSS変数 `--marker-bg-start`、`--marker-bg-end`、`--marker-border`、`--marker-ink`、`--marker-shadow` で定義する。`cyan`、`lime`、`yellow`、`white` は濃色インク、それ以外は明色インクを使う。白は濃い外枠と影を持つ。通常、ホバー、コンテキスト選択、移動元、移動プレビューを形・枠・影・透明度でも区別する。

2Dは位置決め用の外側要素と共通 `.hs-marker` の内側要素を分ける。これにより位置決めの `translate` と菱形の `rotate` が競合せず、360と同じ形状クラスを利用できる。

## 移動状態とイベント

移動は一つの `hotspotMoveState` に、対象、元座標、元DOM、仮DOM、最新ポインター、RAF ID、開始シーンID、世代番号、保存中フラグ、pointerdown情報を保持する。

- `startHotspotMovePreview`: 既存移動を解除し、元マーカーを半透明化し、同じ見た目の仮マーカーを作成してPointer Eventsを登録する。
- `updateHotspotMovePreview`: 最新のクライアント座標だけを保存し、1フレームにつき一度だけ仮DOMを更新する。
- `commitHotspotMove`: 単純なpointerup/clickだけを受け付け、360では `viewer.mouseEventToCoords`、2Dでは画像矩形に対する百分率へ変換する。保存中は二重確定しない。
- `cancelHotspotMove`: Esc、シーン変更、編集終了、モーダル・一覧更新、pointercancel、保存失敗で元表示へ戻す。保存要求の送信後だけはキャンセルせず、応答まで競合する編集・削除・再移動・シーン切替を拒否する。
- `cleanupHotspotMovePreview`: RAF、イベント、仮DOM、元DOMクラス、互換フラグを必ず一括解除する。

ポインター移動量が既存5px閾値を超えた場合はドラッグとして確定せず、移動モードを維持する。2D座標は画像外を拒否し、端点を0〜100へ制限する。保存成功時だけ実マーカーの `pitch` / `yaw` を更新する。非同期応答は開始シーンIDと世代番号が一致する場合だけ適用する。

## 保存と復旧

移動payloadはラベル、説明、リンク、形状、色、アイコン、写真ID、ジャンプ先IDを元argsからコピーし、座標だけを置換して既存 `updateHotspot` を呼ぶ。保存失敗・通信失敗では元argsと実マーカーを変更しない。成功時はキャッシュを破棄してからargsと360/2D描画を更新する。通常CRUDは要求ごとに追跡し、同一シーンの独立操作は互いの応答を破棄しない一方、同一マーカーへの移動と編集・削除は並行させない。

空ラベルは `jumpSceneId` がある場合だけ許可する。読込も同じ条件で行を採用し、ツールチップは従来どおりジャンプ先シーン名を使う。

## テスト

新しいNodeテストで、許可値の完全一致、旧値フォールバック、SVG全定義、UI選択肢、色コントラスト、共通描画経路、2D座標変換、RAF間引き、開始・確定・キャンセル・非同期世代・リスナー破棄を検証する。既存144件を含む全テストを実行し、最後に読み取り専用レビューA/B/Cを並列実施する。再現できた指摘だけ、失敗テストを先に追加して修正し、最終的に197件の回帰テストで確認する。

## 対象外

動画再生、音声再生、外部アイコンライブラリ、既存 `star` 行の一括更新、新しいタッチ専用UIは追加しない。
