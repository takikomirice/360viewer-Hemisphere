# シート基盤改善 第2段階 設計

## 目的と範囲

Drive の対象フォルダ直下にある画像と `scenes` を安全に同期し、画像種別、ホーム、表示順、northOffset を `scenes` 由来の情報として一覧へ結合する。同期は初期表示・一覧更新のルート、ユーザーが開いたサブフォルダ、アップロード先フォルダだけを対象とし、再帰走査、シーン設定 UI、手動並べ替えは行わない。

## 検討した方式

1. **Drive 列挙と scenes 更新をフォルダ単位の同期サービスへ集約する（採用）**
   - Drive の列挙が完了してからロックと scenes 読み取りへ進むため、権限エラーや一時的失敗を削除と誤認しない。
   - 一度の scenes スナップショットから純粋な同期計画を作り、既存の `upsertScenes_` でまとめて保存できる。
2. **画像を列挙するたびに scenes の該当行を検索・更新する**
   - 実装差分は小さいが、画像数に比例して全件読込と書込が増え、同時実行時の重複も防ぎにくい。
3. **起動時にルート以下を再帰同期する**
   - 全データを一度に揃えられるが、Drive API と実行時間の負荷が大きく、今回の非再帰要件に反する。

## 同期アーキテクチャ

`getConfigFromFolder_` は、結合済みキャッシュを利用できる通常経路と、画面イベントから指定される強制同期経路を持つ。同期時は次の順序を固定する。

公開クライアントから指定できるサブフォルダは、親方向だけをたどって config のルート配下であることを確認する。アップロード先にも同じ境界を適用し、範囲確認のためにルートから全サブフォルダを下向き走査しない。

1. 対象フォルダのサブフォルダと対応画像形式を Drive から列挙する。
2. 列挙成功後にスクリプトロックを取得する。
3. `scenes` を一度読み、ファイル ID 索引を利用する。
4. 純粋関数で新規行、既存メタデータ更新、ホーム正規化、結合済み一覧を計画する。
5. 更新配列を一度の `upsertScenes_` 呼び出しで保存する。
6. 変更時は対象フォルダの古いキャッシュを無効化し、完成した結合済み一覧を保存して返す。

Drive 列挙が失敗した場合は scenes と info を開かない。空一覧や一覧からの欠落は成功した「現在の表示対象」として扱うだけで、scenes、info、Drive の削除を一切行わない。同期対象画像がゼロの場合は既存ホームも変更しない。

## scenes の新規登録と既存更新

新規行は Drive ファイル ID、Drive 名と同じ表示名、現在の親フォルダ ID、`360`、`FALSE`、同フォルダ内の最大有限表示順の次の整数、空の northOffset と取得元、Drive 更新日時、同期日時を持つ。複数の新規画像は Drive 名と ID の安定順で連番を割り当てる。同期中に Blob は読まないため、取得元は未取得を示す空欄とする。

新規行だけファイル名の `[2D]` と `[HOME]` を解析する。`[2D]` は種別 `2D`、`[HOME]` はルート画像のホーム候補になる。既存行ではタグを解析せず、種別・ホーム・表示順・northOffset を上書きしない。親フォルダ ID と Drive 更新日時は現状へ追随する。表示名はアプリの名前変更で明示更新し、Drive 更新日時が変わった既存行では部分成功やDrive上の直接改名を修復するためDrive名へ同期する。この表示名同期でもタグを種別・ホームとして再解釈しない。

## ホーム正規化

ルートフォルダを正常に列挙でき、画像が一件以上ある場合だけ実行する。現在列挙できたルート画像のうち、表示順と名前の安定順で次を選ぶ。

1. 既存 scenes で `TRUE` の画像
2. 今回新規登録する `[HOME]` 画像
3. 先頭画像

選択した一件だけを `TRUE`、同じ一覧内の他画像を `FALSE` にする。同期一覧に現れなかった行や未走査のサブフォルダ行は変更しないため、一時的欠落を根拠に状態を消さない。

## クライアントへ返す一覧

画像項目は互換用 `id`、`name` に加え、`driveName`、`displayName`、`parentFolderId`、`type` / `sceneType`、`isHome`、`displayOrder` / `order`、`northOffset`、`northOffsetSource`、`driveUpdatedAt`、`sceneUpdatedAt` を返す。日付は ISO 文字列、真偽値と数値は正規化する。

画像は有限な表示順を優先し、同値・不正値では表示名、Drive 名、ID の順で安定比較する。フォルダは従来どおり名前順で画像より前に置く。フロントは明示的な `2D` / `360` をファイル名より優先し、種別が空の旧行だけ `[2D]` を参照する。ホームは `isHome` を使う。2D 経路では northOffset を Pannellum へ渡さず、360 経路では `0` を失わない。

## アップロード、名前変更、明示削除

アップロードは UI の種別を同期計画への明示上書きとして渡し、元のファイル名で Drive に作成する。作成後に実際の保存先フォルダを強制同期し、返された結合済み画像をクライアントへ返す。scenes 同期失敗でも Drive ファイルを削除せず、`success: true` と `partialSuccess: true`、警告、最低限の画像情報を返す。

名前変更は編集トークン検証後、ロック内で Drive 名、scenes 表示名の順に更新し、親フォルダのキャッシュを無効化する。Drive 成功後の scenes 失敗は部分成功として返し、クライアント上の名前は Drive の成功結果へ合わせる。

削除は編集トークン、ロック、対象確認、Drive ゴミ箱移動、info 削除、scenes の同一 ID 行削除、キャッシュ無効化の順に行う。Drive 失敗時は info/scenes に触れない。Drive 成功後の後処理失敗は残った段階を可能な範囲で続行し、結果へ `partialSuccess`、各段階の成否、警告を含める。同期経路からこの削除関数は呼ばない。

## キャッシュ、エラー、ログ

キャッシュ値は scenes 結合後の一覧とする。アップロード、名前変更、削除、自動登録、ホーム正規化で対象親フォルダを無効化する。同期内では無効化後に完成済み結果を直接キャッシュし、自分自身を再呼出ししない。Drive列挙失敗とscenes失敗は `errorStage` で区別し、Drive・シート更新後のキャッシュ無効化失敗は成功済み段階を保った部分成功として返す。失敗ログには `[scene-sync]` または `[scene-mutation]`、folder/file ID、処理段階を含める。

## テスト方針

Apps Script の Drive、Cache、Lock、Sheet をインメモリで再現し、フォルダ同期の一括登録・冪等性・欠落非削除・Drive 失敗無変更、初回タグ、ホーム正規化、安定順、Blob 非読込を検証する。アップロードはファイル名非変更、UI 種別、部分成功時の非削除を、名前変更・削除は処理順と段階別状態を検証する。フロントは明示種別・ホーム・表示順と northOffset 0 を静的および純粋関数のテストで確認し、既存全テストを回帰として維持する。

## 安全性フォローアップ

公開 `loadHotspots` の northOffset 経路は、フォルダモードでは既存 `scenes` 行、設定ルート配下の行親、種別 `360`、Drive MIME `image/jpeg` の全条件を満たす場合だけ許可する。未登録、ルート外、`2D`、JPEG以外は Blob を読まず `null` を返し、ホットスポット読取自体は継続する。単一画像モードは config の明示ファイルIDと一致する場合だけ読取を許可する。

公開経路の保存は既存行限定の `updateExistingSceneNorthOffset_` に分離し、未登録行や存在しない `scenes` シートを作らない。内部のDrive同期・アップロードだけが通常の scenes 新規登録を担当する。manual保護、`0`、`none` のキャッシュ動作は維持する。

`getImageFileProperties` は `{fileId, __editToken}` payloadを受け、サーバー先頭で編集トークンを検証する。クライアントも `withEditToken` を通す。

既存ファイルの親ID変更を同期計画で検出し、旧親と新親のキャッシュを重複排除して無効化する。失敗したフォルダIDはログと同期結果の `partialSuccess`、`warning`、失敗ID配列へ残すが、成功済み scenes 更新はロールバックせず一覧取得も成功として返す。
