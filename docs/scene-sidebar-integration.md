# シーン一覧の組み込み（2026-09-10）

対象: `improve/quality-audit-20260908`。既存のテストGASのみ更新し、画像の共有設定とシート形式は変更しない。

## 組み込んだ動作

- 実アプリのシーン一覧にJPEGサムネイルと名称を表示。初期画像表示後に最大2件のバックグラウンドRPCで取得する。フォルダ移動後の古い応答は表示に使わず、進行中の古い通信を含めて同時取得を制限する。
- 閲覧者は保存済みサムネイルを読む。不足時には認証済みDriveプレビューを取得するが、Driveへ書き込まない。編集用URLでの起動時には不足分を `Hemisphere Hotspot/thumbnail` へ保存する。
- 保存名は元画像IDとMD5を含む。同じ内容は再生成せず、名前変更だけでは新しいファイルを作らない。並行作成は既存のスクリプトロックで二重作成を防ぐ。画像取得はロックの外で行い、任意URL・任意ファイルのアップロードAPIは追加しない。
- 現在のサムネイルはDriveの縮小プレビュー。試作で作った透視投影WebPの生成ワーカーは組み込んでいない。Driveにプレビューがない場合は名称のみで操作できる。
- PCの一覧幅は200〜480px、かつ画面幅の半分まで。ドラッグ、左右キー、Home/Endで調整でき、ブラウザーへ保存する。パノラマ・2D表示・読み込みオーバーレイが追従する。スマホの下部一覧は維持する。
- 一覧へのマウス移動／フォーカスから180ms後、速度優先モードの次画像を最大1件だけ先読みする。閲覧モードではマーカー情報も取得する。通信量節約設定や2G、高画質、直リンク固定では実行しない。
- 自動配信モードは有効な画像キャッシュまたは先読み通信があれば直接利用する。未取得時は既存の直リンク→GASフォールバックを維持する。

### 実データでの参考測定

Chromeの同じテストデプロイ、速度優先・閲覧モード、16枚の既存画像で観測。計測はクリックからPannellumのload通知まで。繰り返し統計ではなく少数の観測値であり、サーバーキャッシュやネットワーク変動を統制したベンチマークではない。

| 状態 | 観測値 |
|---|---:|
| 更新前、未訪問ポイントへの切り替え2例 | 9,024ms / 6,168ms |
| 更新後、初回シーン表示 | 5,307ms |

先読みの待ち時間は216msに含まれない。更新前の初回表示はマーカー情報取得が30秒以内に終わらず1回タイムアウトしたが、これが恒常的な不具合か一時的な遅延かは未確定。参考ツアーとの同条件比較と低速回線での実測は行っていない。

## 配信方式の残作業

分割画像の生成CLIとローカル比較画面は従来の試作のまま。公開閲覧者が認証・CORS・キャッシュ条件を満たして取得できるタイル配信先が未確定であり、実アプリは正距円筒画像を使用する。タイルごとのGAS往復を追加しても高速化の根拠がないため、外部配信先の判断と実測を待って統合する。

今回の変更だけで参考ツアーと同等の初回速度や未訪問シーンへの速度を保証しない。先読みの時間とクリック後の表示時間は分けて評価する。計測ログの`pannellumLoad`はビューアのload通知であり、最終解像度の全方向描画完了を意味しない。
