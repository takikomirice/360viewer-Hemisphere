# 分割画像・サムネイル配信の設計

## 合意した方針

- 分割読み込みを最優先にする。マップは今回の対象外。
- サムネイルは `Hemisphere Hotspot/thumbnail` に独立した画像として保存し再利用する。
- 起動時に不足を検出する。ただし初期表示は生成を待たない。
- 同時取得数を制限し、届いた画像から表示する。パノラマをサムネイルより優先する。
- メニューは左側を維持し、幅を調整できるようにする。
- 配信方式の比較と選定はCodexが行う。旧コードとの比較条件を記録する。

## 今回の最初の検証単位

本番の配信先を決める前に、再実行可能なローカル実験を用意する。
実画像の権限を変えず、生成物も公開Gitには含めない。
GASの既存5ファイルは、この検証単位では変更・デプロイしない。

1. 正距円筒画像からPannellum互換のキューブ面・多解像度タイルを生成する。
2. 同じ画像から、歪みを抑えた透視投影サムネイルをWebP/JPEGで生成し容量を比較する。
3. 元画像・全体縮小画像・分割画像を同じローカル配信条件で実ビューアに表示する。
4. サムネイルの取得を1並列と4並列で比較する。各結果は到着ごとに表示する。
5. 実Driveの直接配信失敗とGASの記録済み待ち時間を、ローカル配信の結果と区別して記録する。

## 配信候補と判断

- Drive保存＋GAS返送: 既存権限を使えるが、タイルごとのRPC往復は避ける必要がある。
- Drive保存＋静的配信: 推奨候補。生成物を配信用ストレージへ同期し、公開閲覧から直接取得する。
- 外部ツアーサービスへ移行: 今回は採用しない。既存の編集・クイズ・音声を維持する。

ローカル実験は変換品質と読み込み方式の比較を判断するものであり、CDNの実速度やGASの改善を証明しない。
外部公開先をまだ作っていない段階で本番速度の達成を宣言しない。

## 生成ライフサイクル

起動時はマニフェストで不足・旧版を確認する。既存画像または場所名で先に表示する。
管理側の生成処理は元画像の内容ハッシュと生成設定で重複を抑止し、全ファイルの完成後にマニフェストを切り替える。
閲覧者から任意画像や任意URLを保存できるAPIは追加しない。
最初の検証は管理用CLIで実行し、常設の生成実行環境と起動時キューは配信方式の選定後に実装する。
同名のサムネイルを起動ごとに増やさず、名前変更だけでは再生成しない。
タイル一式はサムネイルとは別管理とし、部分生成を完成済みと扱わない。

## 比較条件と完了基準

- 画像と画角・表示サイズを揃える。初回、未訪問切替、再訪を分ける。
- 最初の景色の表示と、ビューアの描画準備完了を区別する。Pannellumのloadイベントを最終解像度完了と呼ばない。
- 使用した元画像がDriveの縮小プレビューなら、その寸法を明記し原寸画像との比較を捏造しない。
- 同時取得・失敗の独立性・重複抑止をテストする。
- 分割画像が実際に表示でき、360度の面の向きが成立することを確認する。
- 起動時の自動生成、Drive永続保存、本番への導入は、試作の完了と区別して進捗報告する。
